# השיריוּנר

אפליקציית שיריון בעברית למחשב ולטלפון. חדרים ומחשבים ניידים, שיריונים חד־פעמיים וקבועים, רשימת מורים מנוהלת, בקשות לאישור, ביטולים וחריגים נקודתיים לסדרה.

## מצב נוכחי

האתר מחובר לפרויקט Firebase בשם hashiryoner ופורסם ב־GitHub Pages. הפונקציה manage וכללי Firestore נפרסו בגרסה הראשונה. השדרוג לרשימת מורים ולבקשות שיריון קבוע דורש פריסה נוספת של הפונקציה והאתר. במצב ללא הגדרת Firebase מוצגת הדגמה מקומית מסומנת.

## הפעלה מקומית

להריץ `npm start` ולפתוח `http://127.0.0.1:4173`. הבדיקות מופעלות עם `npm test`.

## חיבור ופריסה

1. ליצור או לבחור פרויקט Firebase ייעודי ולהפעיל Firestore, כניסה אנונימית וכניסה עם Google.
2. להזין את הגדרות יישום הווב ב־public/config.js. כתובת מנהל מאומתת: nros1978@gmail.com.
3. להתקין תלויות בתיקיית functions ולפרוס באמצעות Firebase CLI את הפונקציות ואת כללי Firestore. הפונקציות עשויות לדרוש מסלול חיוב; אין לאפשר חיוב ללא החלטת הבעלים.
   לפני פריסת מנגנון המייל יש להגדיר את הסודות `SMTP_USER` ו־`SMTP_PASS`. הראשון הוא חשבון Google Workspace השולח והמקבל, והשני הוא סיסמת אפליקציה של Google. אין לשמור את הסיסמה בקובץ או במאגר GitHub.
4. להעלות למאגר GitHub ולהפעיל Pages במצב GitHub Actions. תהליך הפריסה כבר כלול. להוסיף את דומיין Pages לרשימת Authorized domains ב־Firebase Authentication.
5. לבדוק בשני מכשירים הזמנה מקבילה, כניסת מנהל, הרשאות ביטול, ומניעת חריגה במלאי לפני הפצה למורים.

כל הכתיבות בענן עוברות דרך callable function וטרנזקציה; כתיבה ישירה מהדפדפן חסומה. אין הרשאת ניהול על בסיס שם או מצב הממשק. בחירת שם מורה אינה הזדהות מאובטחת; הזדהות המורים נשארת אנונימית מאחורי הקלעים, ללא סיסמה. מחיקת נתוני הדפדפן מאבדת את זיהוי ההזמנות והבקשות האישיות; המנהל עדיין יכול לטפל בהן.

הגרסה משתמשת במסמך משותף לכל המערכת לצורך עקביות. קיימת תקרת 2,000 הזמנות ונדרש להוסיף ארכוב לפני הגעה לתקרה. בקשות מקבילות נבדקות מחדש בתוך הטרנזקציה. הפחתת מלאי או שיעורים שסותרת הזמנה קיימת נחסמת עם הסבר, ללא מחיקת הזמנות.
